# 测试说明

## 环境准备

需要 Go 1.24+、Node.js 22.13+、MySQL 8.0+。所有命令在项目根目录执行。MySQL 使用 InnoDB、utf8mb4，事先创建应用数据库（本机使用 `bigshot`）。

云服务器使用 `bigshot` 的建库、账号授权、建表和结果检查步骤见 [云服务器MySQL建表](云服务器MySQL建表.md)。

复制 `.env.example` 为 `.env`，填写数据库主机、端口、库名、账号、密码，另设至少32字节的随机 `JWT_SECRET` 和8～72字节的 `ADMIN_PASSWORD`。不要提交真实密码。进程环境变量优先于文件配置。

应用数据库账号需要该库内的建表、索引及读写权限。自动集成测试额外需要创建、删除临时数据库的权限。生产环境设置 `APP_ENV=production`、`SEED_DEMO=false` 并使用 HTTPS；开发环境 HTTP 使用 `APP_ENV=development`。

```powershell
npm ci
go mod download
npm run dev
```

访问 http://localhost:5173 ，API为 http://localhost:3001/api/health 。后端自动执行版本化建表和管理员初始化。管理员密码修改只在首次创建账号时生效，不会覆盖已有密码。

## 自动验证

| 命令 | 验证内容 | 需要MySQL |
| --- | --- | --- |
| `npm run typecheck` | Vue/TypeScript 类型检查 | 否 |
| `go test ./server/...` | 配置、JWT、业务校验、联系方式、HTTP权限边界；集成测试默认跳过 | 否 |
| `go vet ./server/...` | Go静态检查 | 否 |
| `npm run build` | 前端类型检查和生产构建、Go二进制编译 | 否 |
| `npm run smoke` | 真实MySQL、HTTP及WebSocket集成测试 | 是 |

`npm run smoke` 不需要提前启动后端。测试会创建 `campus_it<随机值>_test` 临时数据库和临时上传目录，结束后清理自己创建的资源；不向 `DB_NAME` 指定的应用库写入数据。异常退出遗留的临时库，必须确认完整名称和归属后再人工清理。

集成测试覆盖：迁移和演示初始化幂等；注册登录退出、大小写重复、资料和中文/emoji；新闻权限、分享CRUD、搜索排序分页；点赞/收藏、并发点击、评论权限；图片上传、伪装文件、5MB限制；搭子编辑和标签筛选；联系方式隐藏、重复申请、拒绝、并发批准只建一个会话；实时双向推送、历史游标、未读/已读、会话隔离；四类举报、重复举报、上下文证据、下架恢复、删除私信；封禁和解封；关联会话级联删除；跨数据库连接读取持久化数据。

## 手动功能验收

准备普通用户A、B、C和管理员四个独立登录会话。建议使用不同浏览器或浏览器配置文件，同一浏览器普通标签页会共享Cookie。启用演示数据时，普通账号为 `linzhi`、`zhouyu`、`chenmu`，密码 `Demo123!`；管理员以首次初始化配置为准。

| 流程 | 操作 | 预期 |
| --- | --- | --- |
| 首次访问 | 未登录打开首页、交流页、搭子页或详情链接 | 先进入登录/注册页，不展示主页面；已有有效登录会话可直接进入 |
| 确认密码 | 注册时留空、输入不一致、修正为一致；切换至登录 | 确认密码必填；不一致时显示提示并阻止注册；一致后正常提交；登录页不显示确认密码 |
| 登录跳转 | 从搭子详情被引导登录，登录成功后刷新，再退出 | 返回原目标页面；刷新保持登录；退出后再次访问需登录 |
| 浏览与刷新 | 浏览首页、交流、搭子；直接刷新详情URL | 静态资源、日期、深层路由正常 |
| 认证 | 注册、重复注册、错误密码、退出、刷新 | 正确提示；刷新保持登录；退出后受限操作要求登录 |
| 资料 | 修改昵称、简介和头像，刷新 | 内容持久化，中文和emoji正常 |
| 分享/新闻 | A发布和编辑；B尝试编辑删除；普通用户尝试发新闻；管理员发布新闻 | 作者可管理自己的内容；他人受限；新闻仅管理员可发布 |
| 搜索分页 | 搜索命中/空结果，切换类型，超过12条时翻页 | 总数和内容一致，空态清楚 |
| 点赞收藏评论 | B操作点赞、取消、收藏、取消、评论和删除自己的评论 | 状态与数量正确；他人无法删评论 |
| 图片 | 上传四种支持格式、非图片、超过5MB文件 | 正常图片刷新后仍可见；异常文件有提示 |
| 搭子 | A发布并编辑；游客和B查看 | 字段正确；联系方式隐藏 |
| 拒绝申请 | C申请，A拒绝，C再申请 | 显示拒绝，不建立会话，重复申请受限 |
| 同意申请 | B申请，A同意并快速重复审批 | 仅处理一次、仅一个会话，B可看联系方式 |
| 私信 | A与B双向聊天、切换会话、刷新 | 实时显示且不重复，历史保留，未读/已读更新 |
| 会话隔离 | C访问A/B会话的读写接口 | 返回404，不能读取或发送 |
| 举报 | 分别举报分享、搭子、用户、私信，再重复举报 | 待处理记录可见，同一待处理举报不重复 |
| 审核 | 管理员下架、恢复、删除、驳回举报和删除私信 | 公共可见性正确，处理状态与证据正确 |
| 封禁解封 | A保持登录时被封禁，再解封 | 旧会话无法操作，不能登录；解封可登录，内容需管理员另行恢复 |
| 删除搭子 | 删除已建立聊天的搭子邀请 | 按原业务关系级联清理申请、会话和消息，无孤立会话 |

## 浏览器、网络和部署验收

在桌面 Chrome/Edge 和手机浏览器检查登录、发帖、申请、聊天，确认外观与原版一致，手机键盘不遮挡关键操作，长文本和错误提示可读。测试离线/恢复、关闭消息页再返回、登录过期、多标签页和快速切换会话，记录持续报错、重复连接、丢失或重复消息。自动API测试不能代替这些浏览器体验检查。

```powershell
npm run build
.\server\bin\server.exe
```

Linux执行 `./server/bin/server`，访问 http://localhost:3001 。从其它目录启动时使用 `-root 项目根目录`。生产环境确认HTTPS、Cookie的HttpOnly/Secure/SameSite、WSS握手、代理超时和上传大小限制。通过HTTP访问production环境可能导致登录Cookie无法发送。

重启后检查用户、帖子、申请、消息、图片仍存在。将MySQL和上传目录一起备份，实际恢复至另一独立环境，验证关联关系和图片。不要通过删除数据库来改密码或升级结构。

## 排错

| 现象 | 处理 |
| --- | --- |
| 配置校验失败 | 检查JWT密钥、管理员密码长度和生产演示开关 |
| MySQL连接失败 | 检查服务、TCP端口、DB_USER/DB_PASSWORD、账号连接权限 |
| Unknown database | 先创建DB_NAME；应用只自动建表 |
| 建表/测试建库被拒绝 | 补充应用库内权限；测试额外需要CREATE/DROP DATABASE |
| 修改.env后管理员密码不变 | 使用首次创建密码，已有账号不自动重置 |
| 前端提示尚未构建 | npm run build，或访问5173开发服务 |
| WebSocket握手失败 | 检查Cookie、同源访问和反向代理Upgrade |
| 图片丢失 | 检查UPLOAD_DIR路径、持久化和权限 |
| Go测试中集成测试SKIP | 默认行为，使用npm run smoke显式运行 |
