# 校园邮箱验证与 SMTP 配置

## 两种邮箱的用途

网站发送验证码需要一个发信邮箱。用户注册时填写的是收信校园邮箱，两者可以不同。SMTP配置只放在后端 `.env` 中，不放进前端源码。

当前允许注册的邮箱后缀由项目根目录 `.env` 的一行控制：

```dotenv
CAMPUS_EMAIL_DOMAIN=smail.nju.edu.cn
```

填写一个域名，不带 `@`、`https://` 或逗号；只匹配这个完整域名，不自动包含其它子域名。保存后重启后端生效。前端会向后端读取此配置，展示允许的后缀，无需另改前端代码。

## 使用南大学生邮箱发验证码

学校官方的[学生邮箱客户端配置说明](https://itsc.nju.edu.cn/_s302/1a/8f/c21586a334479/page.psp)给出的参数为：SMTP主机 `smtp.exmail.qq.com`、SSL端口465、账号使用完整学生邮箱。学校的[邮箱问答](https://itsc.nju.edu.cn/96/2e/c21475a497198/pagem.htm)说明，开启微信扫码登录后须使用客户端专用密码。

1. 在自己电脑的浏览器登录 [南大学生邮箱](https://mail.smail.nju.edu.cn/)，按学校要求完成扫码登录。
2. 进入邮箱的“设置 → 客户端设置”，开启 IMAP/POP/SMTP 服务并保存。若界面名称有变化，查找“SMTP”或“客户端服务”。
3. 打开“微信绑定”，在“客户端专用密码”处点击“生成新密码”，生成供本项目使用的密码。若界面入口有变化，参考邮箱页面的帮助或学校官方说明，不要关闭安全登录来绕过。
4. 将生成的客户端专用密码填入下面的 SMTP_PASSWORD。不要把网页登录密码、统一身份认证密码或本站管理员密码混填进去，也不要把专用密码提交到Git或发到聊天。
5. 在云服务器的项目根目录执行 `nano .env`，添加或修改：

```dotenv
CAMPUS_EMAIL_DOMAIN=smail.nju.edu.cn
SMTP_HOST=smtp.exmail.qq.com
SMTP_PORT=465
SMTP_TLS_MODE=tls
SMTP_USERNAME=你的学号@smail.nju.edu.cn
SMTP_PASSWORD=刚刚生成的客户端专用密码
SMTP_FROM=你的学号@smail.nju.edu.cn
```

SMTP_USERNAME和SMTP_FROM填写同一个实际发信邮箱。`mail.smail.nju.edu.cn`是网页登录地址，SMTP_HOST应使用官方给出的发信主机；SMTP_HOST不能包含协议前缀或端口。

## 构建、迁移与重启

这次新增3张表，由 `002_email_verification.sql` 管理，分别保存邮箱绑定、验证码摘要和发送频率。原有用户和业务数据会保留，管理员和旧账号无需补邮箱即可继续登录。新的公开注册接口始终要求邮箱验证码。

首次部署新代码时，在Linux项目根目录执行：

```bash
npm ci
npm run build
./server/bin/server -migrate-only
```

正常停止旧后端后，再启动一次 `./server/bin/server`；如果已经配置systemd，则重启对应服务。避免同时启动多个进程争用3001端口。之后仅修改SMTP或邮箱后缀的 `.env` 配置时，重启后端即可，无需重新构建。

SMTP_HOST留空时，已有账号登录和其它功能仍然可用，但注册页面会提示邮件服务未配置；发送验证码接口返回503，不会生成绕过验证的账号。

## 发信网络与排错

阿里云ECS的25端口默认受限，[官方建议使用465端口发信](https://help.aliyun.com/zh/ecs/network-connectivity-faqs)。本项目使用465/TLS，服务器需要能向SMTP主机发起出站连接；不需要为SMTP在实例入方向开放465。

可以在服务器验证TLS连接：

```bash
openssl s_client -connect smtp.exmail.qq.com:465 -servername smtp.exmail.qq.com -brief
```

完成观察后按Ctrl+C退出。这只能验证网络和证书，不能证明邮箱账号认证或实际投递成功。

| 现象 | 检查 |
| --- | --- |
| 页面提示尚未配置 | SMTP_HOST是否填写；是否重启了实际运行的后端；是否仍为旧版本进程 |
| timeout | DNS、服务器出站网络、SMTP465端口是否可达 |
| 535/认证失败 | 完整邮箱账号、客户端专用密码、客户端服务开关；必要时重新生成专用密码 |
| 发送失败/拒绝投递 | 邮箱账号的发信状态、发信人是否与SMTP账号一致、服务端日志 |
| 网站提示已发送但没收到 | 收件地址是否正确；收件箱和垃圾邮件；发件邮箱的发信查询/退信记录 |
| 收到后提示过期 | 验证码自SMTP接受邮件后60秒有效，邮件投递延迟也会占用有效期；重新发送后使用新码 |

验证码为6位数字，60秒有效，每个邮箱60秒内只能发送一次，每份验证码最多尝试5次，成功注册后立即作废。同一邮箱只能绑定一个账号。每个直接连接来源IP每小时最多预约60次发信；部署到反向代理后若大量请求来自同一个代理IP，会共享这个限额。

## 人工验收

输入允许域名的真实校园邮箱，点击右侧“发送验证码”，检查邮件并在60秒内填写验证码及其它注册字段，确认注册成功并自动登录。另测不允许的后缀、空验证码、错误码、过期码、重复发送、重复绑定、SMTP密码错误和后端重启后继续验证。验证码不出现在API响应或应用日志中，邮件可能受服务商投递策略影响，需以真实收件结果完成最后验收。
